## The problem

### Writing code got faster. Shipping didn’t.

Faros AI studied 10,000 developers on 1,255 teams. Teams with high AI adoption merged **98% more pull requests**, {gold:but review time rose 91%.}

[Faros AI, The AI Productivity Paradox, 2025 · vendor telemetry study](https://www.faros.ai/ai-productivity-paradox)

*Image alt:* A pull-request list shows 63 open agent-written changes awaiting review by two reviewers. A red handwritten note reads: More code. Same two reviewers.

### AI amplifies whatever your process already is.

DORA’s 2025 report describes AI as an **amplifier** of an organization’s existing strengths and weaknesses. {gold:The returns come from the underlying system, not the tools.}

[DORA, State of AI-assisted Software Development 2025](https://dora.dev/dora-report-2025/)

*Image alt:* Three coding agents work in parallel on one invoicing app, each assuming something different about billing, and a banner warns that three changes touch checkout. A red handwritten note reads: Three agents. Three different products.

### Without evidence, you can’t tell fast from fragile.

In a randomized trial of 16 experienced open-source developers, tasks took **19% longer** with AI tools. {gold:Afterward, they still believed AI had made them 20% faster.}

[METR, 246 real tasks, early-2025 tools](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)

## The solution

### Give every agent the same product intent

Write down the product goals, architecture, constraints, and code patterns before work is delegated. {gold:People keep ownership of the product decisions and tradeoffs.}

*Image alt:* An editor shows a product folder with intent, architecture, constraints, and patterns files. The open intent file lists what customers should be able to do and notes that pricing and refunds need a person’s decision, owned by the product lead.

### Turn what works into a repeatable process

Experiment first, then encode what works as skills: clear inputs, explicit dependencies, and defined completion criteria. {gold:Isolate concurrent changes and let an orchestrator coordinate the workers.}

*Image alt:* A skill file feeds three isolated worktrees with different statuses, which report to an orchestrator that coordinates the workers, verifies, and merges.

### Build trust into the factory

At every level of delegation, ask {gold:what evidence lets you trust the result?} Meaningful tests, review, CI/CD, and product-level QA. Then grow the factory with your team, one step at a time.

*Image alt:* A merge checklist shows tests, code review, staging integration, product QA of the checkout flow, and rollback plan all complete. A red handwritten note reads: Evidence, not hope.
